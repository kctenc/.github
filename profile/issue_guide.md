# 🆕 GitHub Issue 작성 가이드

Issue는 **새로운 개발 작업을 요청할 때** 사용합니다.

새로운 기능, 개선사항, 오류 수정 등 **현재 진행 중인 작업과 별개의 새로운 요청사항**이 있다면 해당 Repository에 Issue를 등록해주세요.

> 💡 이미 진행 중인 작업의 수정이나 추가 요청이라면 새로운 Issue를 만들지 않고 **Project의 기존 작업에 코멘트**를 작성해주세요.

---

# 1. 요청할 Repository 선택

먼저 요청하려는 작업과 관련된 Repository를 선택합니다.

| 요청 내용 | Repository | 바로가기 |
|---|---|---|
| 🌐 대시보드 / 웹 화면 | Frontend | [➕ Issue 등록](https://github.com/kctenc/meerkat-dashboard-fe/issues/new/choose) |
| ⚙️ 서버 / 데이터 | Backend | [➕ Issue 등록](https://github.com/kctenc/meerkat-dashboard-be/issues/new/choose) |
| 📡 센서 / 게이트웨이 통신 | TCP / Socket Server | [➕ Issue 등록](https://github.com/kctenc/meerkat-server-new-refactoring/issues/new/choose) |
| 📱 모바일 앱 | Application | [➕ Issue 등록](https://github.com/kctenc/meerkat_app/issues/new/choose) |

어디에 등록해야 할지 정확히 모르겠다면 요청사항과 **가장 관련 있어 보이는 Repository**에 등록해주세요.

---

# 2. New Issue 선택

Repository의 **Issues** 메뉴로 이동합니다.

오른쪽에 있는 **New issue** 버튼을 클릭합니다.

Issue Template이 표시되는 경우 요청 내용에 맞는 항목을 선택합니다.

### Feature

새로운 기능 또는 기능 개선을 요청할 때 사용합니다.

예시:

- 검색 기능 추가
- 그래프 기능 추가
- 새로운 버튼 추가
- 화면 기능 개선

### Bug

현재 정상적으로 사용되어야 하는 기능에서 **오류가 발생하는 경우** 사용합니다.

예시:

- 버튼을 눌러도 동작하지 않음
- 그래프가 표시되지 않음
- 앱이 종료됨
- 데이터가 잘못 표시됨

### Task

그 외 일반적인 개발 작업이나 확인이 필요한 작업에 사용합니다.

정확한 종류를 모르겠다면 가장 가까운 항목을 선택하면 됩니다.

---

# 3. 제목 작성

제목만 보고도 **어떤 작업을 요청하는지 알 수 있도록** 작성해주세요.

### 👍 좋은 예시

> 대시보드 그래프 X/Y축 선택 기능 추가

> 현장 목록 검색 기능 추가

> 모바일 앱 알람 클릭 시 현장 화면 이동 기능 추가

> 센서 그래프가 표시되지 않는 오류 수정

### 👎 피해야 할 예시

> 수정해주세요

> 기능 추가

> 오류

> 확인해주세요

---

# 4. 요청 내용 작성

개발 방법이나 전문적인 기술 내용을 작성할 필요는 없습니다.

**현재 상태 → 요청사항 → 원하는 결과** 순서로 작성하면 담당자가 이해하기 쉽습니다.

### 권장 작성 방법

> **현재 상황**
>
> 현장 상세 화면의 센서 그래프에서 X축과 Y축 데이터가 동시에 표시되고 있습니다.
>
> **요청사항**
>
> X축과 Y축을 사용자가 선택해서 볼 수 있도록 변경해주세요.
>
> **원하는 결과**
>
> - X 선택 → X축 데이터만 표시
> - Y 선택 → Y축 데이터만 표시
> - 필요에 따라 X/Y를 변경할 수 있도록 적용
>
> **참고사항**
>
> PC와 모바일 화면 모두 동일하게 적용되었으면 좋겠습니다.

---

# 5. 이미지 첨부

화면과 관련된 요청이나 오류는 가능하면 **화면 캡처를 첨부해주세요.**

특히 수정이 필요한 위치를 이미지에 표시하면 담당자가 요청사항을 더 빠르게 이해할 수 있습니다.

이미지는 다음 방법으로 첨부할 수 있습니다.

- 이미지 파일을 작성창에 드래그
- 복사한 이미지 붙여넣기
- Windows : `Ctrl + V`
- Mac : `Command + V`

### 예시

> 아래 이미지에서 빨간색으로 표시한 위치에 검색 버튼을 추가해주세요.
>
> `[화면 캡처 첨부]`

---

# 6. 담당자 지정

담당자를 알고 있다면 우측의 **Assignees**에서 담당자를 지정할 수 있습니다.

담당자를 정확하게 모르는 경우에는 지정하지 않아도 됩니다.

특정 담당자에게 확인을 요청하고 싶다면 본문이나 코멘트에서 `@아이디`를 사용할 수도 있습니다.

예시:

> @담당자아이디 확인 부탁드립니다.

---

# 7. Issue 등록

모든 내용을 작성했다면 **Create issue** 버튼을 클릭합니다.

등록이 완료되면 다음과 같이 Issue 번호가 생성됩니다.

> `#125 대시보드 그래프 X/Y축 선택 기능 추가`

이후 담당자가 Issue를 확인하고 작업을 진행합니다.

---

# 8. 등록 후 추가 내용이 생긴 경우

Issue를 등록한 이후 같은 작업에 대한 추가 내용이 생겼다면 **새로운 Issue를 다시 만들지 않습니다.**

기존 Issue 또는 Project에서 해당 작업을 찾아 **코멘트로 추가 내용을 작성**해주세요.

예시:

> 추가 요청사항이 있습니다.
>
> X/Y축 선택 기능 적용 시 마지막으로 선택했던 축이 유지되었으면 좋겠습니다.

---

# ✏️ 간단한 Issue 작성 양식

어떻게 작성해야 할지 모르겠다면 아래 형식을 사용해주세요.

> **요청 위치**  
> 대시보드 → 현장 상세 → 센서 그래프
>
> **현재 상황**  
> X축과 Y축 데이터가 동시에 표시되고 있습니다.
>
> **요청사항**  
> X축과 Y축을 각각 선택해서 볼 수 있도록 변경해주세요.
>
> **원하는 결과**  
> X를 선택하면 X축만, Y를 선택하면 Y축만 표시되었으면 좋겠습니다.
>
> **참고 이미지**  
> 화면 캡처 첨부

# 📌 핵심 정리

**새로운 작업 요청**

`관련 Repository 선택`  
↓  
`Issues`  
↓  
`New issue`  
↓  
`제목 및 요청사항 작성`  
↓  
`필요한 경우 이미지 첨부`  
↓  
`Create issue`

> **개발 방법을 설명할 필요는 없습니다.**
>
> **어디에서 → 현재 어떤 상태인지 → 어떻게 변경되었으면 하는지**를 작성해주세요.
