# GitHub Issues 희망 작업 등록 가이드

GitHub의 **Issues**는 개발팀에게 **새로운 기능, 수정사항, 개선사항, 오류 등을 요청하기 위한 공간**입니다.

예를 들어 다음과 같은 내용을 등록할 수 있습니다.

- 새로운 기능 추가 요청
- 기존 기능 개선 요청
- 화면 디자인 수정 요청
- 오류 수정 요청
- 데이터 표시 방식 변경 요청
- 기타 개발이 필요한 사항

등록된 Issue는 이후 담당자가 확인하여 개발 업무로 진행하게 됩니다.

---

## 1. Repository 접속

작업을 요청할 프로그램의 **Repository(저장소)**로 이동합니다.

예를 들어 요청하려는 내용에 따라 해당 Repository를 선택합니다.

- 서버 관련 → 서버 Repository
- 웹 대시보드 관련 → 프론트엔드 Repository
- 모바일 앱 관련 → 애플리케이션 Repository

어떤 Repository에 등록해야 할지 모르는 경우에는 담당자에게 확인 후 등록해주세요.

---

## 2. Issues 메뉴 선택

Repository 상단 메뉴에서 **Issues**를 클릭합니다.

기존에 등록된 요청사항과 현재 진행 중인 업무를 확인할 수 있습니다.

새로운 작업을 요청하려면 우측의 **New issue** 버튼을 클릭합니다.

---

## 3. Issue 종류 선택

Issue Template이 설정되어 있는 경우 등록하려는 내용과 가장 가까운 항목을 선택합니다.

예시:

**Feature**  
새로운 기능이나 개선사항을 요청할 때 사용합니다.

**Bug**  
현재 기능에서 오류나 비정상적인 동작이 발생할 때 사용합니다.

**Task**  
기타 개발 작업이나 일반적인 작업을 요청할 때 사용합니다.

정확한 종류를 모르겠다면 가장 가까운 항목을 선택하면 됩니다.

---

## 4. 제목 작성

제목에는 **무엇을 요청하는지 한눈에 알 수 있도록** 작성합니다.

### 좋은 예시

> 대시보드 그래프 X/Y축 선택 기능 추가

> 현장 목록에 검색 기능 추가

> 모바일 앱 로그인 화면 오류 수정

> 알람 목록에서 위험 단계만 조회하는 기능 추가

### 피해야 할 예시

> 수정해주세요

> 기능 추가

> 오류 있음

제목만 보고도 어떤 작업인지 대략적으로 알 수 있도록 작성하는 것이 좋습니다.

---

## 5. 희망 작업 내용 작성

본문에는 **현재 상황과 원하는 결과**를 작성해주세요.

개발 용어나 기술적인 내용을 몰라도 괜찮습니다.

사용자 입장에서 **“현재는 어떻게 되어 있고, 앞으로 어떻게 되었으면 좋겠다”**를 설명하면 됩니다.

### 작성 예시

> **요청 내용**
>
> 현재 대시보드 그래프에서는 X축과 Y축 데이터가 동시에 표시되고 있습니다.
>
> 사용자가 X축 또는 Y축을 선택해서 원하는 데이터만 확인할 수 있었으면 좋겠습니다.
>
> **희망 동작**
>
> - X 버튼 선택 → X축 데이터만 표시
> - Y 버튼 선택 → Y축 데이터만 표시
> - X/Y 버튼을 이용하여 자유롭게 변경 가능
>
> **참고사항**
>
> PC와 모바일 화면 모두 동일하게 적용되었으면 좋겠습니다.

개발 방법이나 구현 방법까지 작성할 필요는 없습니다.

**어떤 기능이 필요한지, 어떻게 동작했으면 좋겠는지**를 중심으로 작성해주세요.

---

## 6. 이미지 첨부

화면과 관련된 요청은 가능하면 **이미지를 첨부하는 것을 권장합니다.**

화면을 캡처한 뒤 수정이 필요한 부분을 표시하면 담당자가 요청 내용을 빠르게 이해할 수 있습니다.

이미지는 Issue 작성창에 다음 방법으로 첨부할 수 있습니다.

- 이미지 드래그
- 이미지 복사 후 `Ctrl + V`
- Mac에서는 `Command + V`

### 예시

> 아래 이미지에서 표시한 위치에 검색창을 추가했으면 좋겠습니다.
>
> [화면 캡처 이미지 첨부]

## 7. 담당자 지정

담당자를 알고 있다면 우측의 **Assignees**에서 담당자를 선택할 수 있습니다.

담당자를 정확하게 모르는 경우에는 비워두어도 됩니다.

필요한 경우 Issue 내용에서 `@아이디`를 사용하여 담당자에게 확인을 요청할 수도 있습니다.

예시:

> @담당자아이디 해당 기능 검토 부탁드립니다.

---

## 8. Issue 등록

작성한 내용을 확인한 후 **Create issue** 버튼을 클릭합니다.

Issue가 등록되면 해당 요청에 고유 번호가 생성됩니다.

예시:

> #125 대시보드 그래프 X/Y축 선택 기능 추가

이후 해당 Issue에서 작업 진행 상황과 담당자의 코멘트를 확인할 수 있습니다.

---

## 9. 추가 요청사항은 코멘트로 작성

Issue를 등록한 이후 추가로 전달할 내용이 생겼다면 새로운 Issue를 다시 만들기보다 **기존 Issue의 코멘트에 추가 내용을 작성**해주세요.

예시:

> 추가 요청사항이 있습니다.
>
> X/Y축 선택 기능 적용 시 사용자가 마지막으로 선택한 축이 유지되었으면 좋겠습니다.

관련 내용을 하나의 Issue에서 관리하면 요청사항과 개발 진행 과정을 쉽게 확인할 수 있습니다.

## 기능 추가 요청

>

# 작성할 때 기억해주세요

Issue를 등록할 때 가장 중요한 것은 **개발 방법을 설명하는 것이 아니라 원하는 결과를 정확하게 전달하는 것**입니다.

가능하면 다음 내용을 포함해주세요.

- **어디에서** 필요한 기능인지
- **현재 어떻게 되어 있는지**
- **무엇이 불편한지**
- **어떻게 변경되었으면 하는지**
- 필요한 경우 **화면 캡처**

### 간단한 작성 양식

> **요청 위치**  
> 대시보드 → 현장 상세 → 센서 그래프
>
> **현재 상황**  
> X축과 Y축 데이터가 동시에 표시됩니다.
>
> **희망 작업**  
> X축과 Y축을 선택해서 볼 수 있도록 변경해주세요.
>
> **참고 이미지**  
> [이미지 첨부]

---

## 핵심 정리

**Repository 접속 → Issues → New issue → 제목 작성 → 희망 작업 내용 작성 → 이미지 첨부 → Create issue**

개발 지식이 없어도 괜찮습니다.

**“현재 상태 → 불편한 점 → 원하는 결과”** 순서로 작성하면 담당자가 요청사항을 이해하기 쉽습니다.
